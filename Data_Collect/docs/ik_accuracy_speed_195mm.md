# 195 mm TCP 下两套 IK 的精度和耗时比较

日期：2026-11-16。对比实验当时的 `Data_Collect` 与 `Piper_DM (2)/QuestArmTeleop` 的 Piper-X 配置。两套程序的 Piper/Piper-X 遥操驱动、IK，以及 Data_Collect 的 FK/标定模板已统一为 `[0,0,0.195,0,0,0]`。

后续按用户要求，Data_Collect 的 Piper-X joint6 限位由 ±120° 改为官方的 ±170°。以下 URDF 哈希及求解结果保留为该修改之前的实验记录，不能用来断言两个当前检出的 URDF 文件仍完全相同；主链坐标定义和 TCP 未因该限位修改而改变。

## 结论

在本次三个连续可达轨迹的 240 个目标上，**Data_Collect 更适合当前精度优先的遥操采集**：位置和姿态残差更小，求解中位耗时仅增加约 0.14 ms。QuestArmTeleop 的中位求解耗时略低；当前默认权重与向零位正则会偏好以位置误差换取更小的关节角。

这个结论不能扩展成全部姿态或实机精度保证。附加的精确零位测试中，两套求解器都出现 `Invalid_Number_Detected`，见下文。

## 实验方法

- 临时独立 conda 环境：Python 3.11.17、Pinocchio 3.2.0、CasADi 3.6.7、NumPy 1.26.4，CPU 为 Intel Core Ultra 9 275HX。BLAS/OpenMP/MKL 线程数设为 1。
- 从两份源码直接提取并执行原 `ArmIK` 类及坐标变换函数，不重写误差函数或求解器，不启动 ROS、CAN、Quest、相机和触觉。
- 两份 Piper-X URDF 的 SHA-256 完全相同：`e83d6e8f4e178a3b7399b8d866e0e42dc2ba21bc034ef343e25b46497d02a580`。
- QuestArmTeleop 当前检出缺少 URDF 引用的 mesh 目录。实验仅通过资源查找路径借用 Data_Collect 的同名网格，未改动参考项目的 URDF 或求解逻辑。这是模型加载准备，不是碰撞能力验证。
- 取接近零位但不在边界、工作空间中部、折叠姿态三个起始关节配置，每组生成 80 个平滑可达 FK 目标，共 240 个。每次向两个求解器提供完全相同的目标和上一参考关节反馈；夹爪反馈固定为 0.03 m。
- 每组独立初始化并预热，交替调用顺序。计时为预热后一次生产 `solve()` 的墙钟时间，包含 Data_Collect 自带诊断开销，排除 ROS、硬件、渲染、模型构造和首次调用。
- 反馈为模拟的上一条参考关节，不含真实机械臂跟踪滞后、传感器噪声或柔性变形。测试覆盖当前默认配置差异，不是只改变一个数学公式的消融实验。

位置误差是 `||FK(q_solution).translation - target.translation||`；姿态误差是相对旋转的最短角。**这些是同一运动学模型内的数值残差，不是机械臂实测定位精度。** 不设置额外精度阈值或评分门槛，收敛状态直接读取 IPOPT。

## 总体结果

| 指标 | Data_Collect | QuestArmTeleop |
|---|---:|---:|
| IPOPT Solve_Succeeded | 240/240 | 240/240 |
| 位置残差中位数 | 0.0089 mm | 9.5031 mm |
| 位置残差 P95 | 0.0323 mm | 14.8477 mm |
| 姿态残差中位数 | 0.0181° | 0.1125° |
| 姿态残差 P95 | 0.0426° | 0.1600° |
| 求解墙钟时间中位数 | 1.646 ms | 1.504 ms |
| 求解墙钟时间 P95 | 2.502 ms | 2.224 ms |
| 求解墙钟时间最大值 | 2.943 ms | 2.761 ms |
| IPOPT 迭代次数中位数 | 4 | 5 |

两套热求解耗时均小于当前 30 Hz 目标输入的约 33 ms 周期；这不能推导出整套遥操的端到端延迟或实际可持续频率。单次机器负载、CPU 调频和数值库版本也会影响耗时，约 0.14 ms 的差距不宜解读为普遍的算法速度优势。

## 差异原因

1. **位置项权重**：Data_Collect 为 20，QuestArmTeleop 为 2。代码使用 `sumsqr(w_pos * error)`，相同数值残差的系数相差 100 倍，因此 Data_Collect 更倾向于消除位置偏差。
2. **正则参考**：Data_Collect 使用 `||q-q_feedback||²`，参考版使用 `||q||²`。参考版在非零姿态会持续受到向零位的偏好，末端精度可被牺牲；不是 IPOPT 没有收敛。相同 `tol=1e-4` 不代表相同末端误差。
3. **误差定义**：Data_Collect 直接优化 XYZ 位置差；参考版使用 SE(3) `log6` 的平移分量。姿态误差较小时两者接近，大姿态误差下并不等价。
4. **平滑与诊断**：Data_Collect 保留上次成功发布解，并额外计算 FK 残差与求解诊断；参考版反馈回调重置平滑参考。Data_Collect 的这些计算包含在计时中。
5. **变量维度**：实际检查 Data_Collect 为 6 维，参考版为 7 维。参考 YAML 锁定了固定的 `gripper_base_joint`，却没有锁定可动 `gripper`，夹爪仍进入优化。它不影响挂在 joint6 下的 TCP，但增加一个变量。实验保留这个原始配置，没有在比较中悄悄修正。

## 精确零位的边界结果

额外分别从全零关节反馈求解两个目标：零位本身，以及由 `[0,0.02,-0.02,0,0,0]` 生成的可达目标。

- 零位本身两者返回 Solve_Succeeded；Data_Collect 的模型位置残差约 0.182 mm，参考版约 3.079 mm。
- 第二个目标两者都出现 `Invalid_Number_Detected`，日志指向目标函数梯度中的 NaN。
- 临时将初值夹到关节边界内 1e-5 rad 并未解决该案例，因此不能简单归因于关节边界；应继续针对当前 log6/CasADi 的姿态误差导数做数值稳定性修复。

本次按请求修改 TCP 并比较现有 IK，没有引入新的运动保护，也没有同时重写误差算法以掩盖上述边界问题。对于零位启动、保持姿态的纯平移、不可达目标和大角度输入，两套 IK 都不能仅凭这 240 个成功样本宣称可靠；本次明确发现的零位 NaN 应作为后续实机使用前的优先修复项。
